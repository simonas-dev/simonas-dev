# M3 — Day / night

Question: best implementation plan for M3 of PLAN.md given scout context (`.council/M3-scout.md`).
Scope: M3 checklist only. Non-goals: M4 (paper.png, surfaces, throttle), M5 (htmx), M6 (stars, sun/moon glow, reduced-motion waves, visibilitychange, favicons).

## Plan (ordered steps)

1. **Spike + shader night sky** (`static/shader/ocean.frag.glsl`): with `__ocean.night=1` under SwiftShader, sample the canvas behind the hero text. By arithmetic the PLAN night endpoints (dark 0.05, light 1.00) leave the sky near-white (~0.87) while night ink is `#e8e6e1` → ~1.1:1. Fix in the shader so the night sky is dark: e.g. darken the scene/sky gray by `u_night` before the endpoint mix (`gray *= mix(1.0, k, u_night)`, or an equivalent sky term), keeping PLAN's grain formula and endpoints. Target: hero h1 ≥ 3:1 and body/footer text ≥ 4.5:1 for `#e8e6e1` against sampled pixels at night, with the water still readable as an ocean (moonlit, not black). Keep the day output byte-identical in behaviour (u_night=0 → no change).
2. **`templates/base.html`**:
   - Inline script in `<head>` **before** the stylesheet: `try{var t=localStorage.getItem('theme')}catch(e){}if(t=='night'||t!='day'&&matchMedia('(prefers-color-scheme: dark)').matches)document.documentElement.classList.add('theme-night')`. It must **not** touch `window.__ocean` (ocean.js returns early if it exists).
   - `<script src="/site.js" defer>` after ocean.js.
   - Toggle keeps `disabled` in HTML (inert without JS); label `Theme: Auto`; site.js enables it.
   - `<meta name="color-scheme" content="light">` stays; `.theme-night{color-scheme:dark}` covers night.
3. **`static/styles.css`**: `@property --paper/--ink/--surface` (`syntax:'<color>'`, `inherits:true`, day initial values; `--surface` day value = paper). One transition on `html`: `transition: --paper var(--dur-theme) var(--ease), --ink …, --surface …`. No extra per-element background/color transitions (double easing). No transition on first load (class is set before first paint, so nothing to transition). Toggle: `cursor:pointer`, ≥24×24 hit area; keep `:disabled` dim style for no-JS. Crossfade stays under reduced motion (it's a colour fade, not motion).
4. **`static/ocean.js`** (≤ 10,240 B; trim comments if needed): `state.redraw = function(){ if (isStatic && program && !gl.isContextLost()) drawStatic(); }`, called from `onResize` instead of the inline condition. Seed `night` from the class at state creation (`night: +root.classList.contains('theme-night')`). No tween logic in ocean.js; the render loop already uploads `state.night` every frame.
5. **`static/site.js`** (new, plain IIFE, ~1 KB):
   - Delegated click on `.theme-toggle` (survives M5 swaps). Enable the button on init.
   - Cycle auto → night → day → auto. Store `'night'`/`'day'` under key `theme`; remove the key for auto; all storage in try/catch.
   - Button text Auto/Night/Day, `aria-label="Theme: <State>"` (label-in-name), no aria-pressed.
   - `matchMedia('(prefers-color-scheme: dark)')` `change` listener, applied only in auto.
   - Apply = toggle `.theme-night` on `<html>` + tween `__ocean.night` from its current value to target over 900 ms with `p=min(1,dt/900); v=a+(b-a)*p*p*(3-2p)` (exactly the cubic-bezier(1/3,0,2/3,1)), rAF, cancel prior tween, call `__ocean.redraw && __ocean.redraw()` each tick. No-op shader part if `__ocean` is missing.
6. Harness (outside repo, `/tmp/pw`): update m2check expectations (toggle focusable, 3 scripts incl. inline + livereload under serve); add `m3check.mjs`.

## Acceptance checks

- **Toggle**: clicks cycle storage unset → `night` → `day` → unset with text/label following; reload preserves state; `colorScheme:'dark'` emulation + auto → `.theme-night`, live flip works in auto but not in day; Enter/Space work; storage throwing → no errors.
- **Class + CSS**: reload in night shows no light frame (screenshot at DOMContentLoaded); computed `--paper` at ~450 ms is between endpoints, at ≥950 ms equals `#1a1a1a`; NOGL night is fully dark with ink ≥ 4.5:1.
- **u_night**: `__ocean.night` ≈0.5 at 450 ms, exactly 0/1 after 950 ms; mid-tween reversal continuous; static tier (SLOW=40) redraws; ocean.js ≤ 10,240 B; `node --check` both JS files.
- **Night contrast**: sampled shader pixels behind hero text at night give ≥3:1 (h1) / ≥4.5:1 (p, footer) against `#e8e6e1`; day screenshot unchanged vs M2.
- **Global**: `zola check`/`zola build` pass; no console errors; built HTML has inline script + ocean.js + site.js.

## Deferred

- Stars, sun/moon glow (M6); reduced-motion wave slowing, visibilitychange (M6).
- No-JS CSS-only `prefers-color-scheme` fallback (no-JS users get day).
- aria-live announcement of theme change.
- Brief "Auto" label before site.js runs (accepted).

## Owner decisions (autopilot)

- Night sky darkened in the shader (deviation from PLAN night formula, like M1's day endpoints) so light ink stays readable — designer recommendation; perf/skeptic listed it as option (a).
- Tween lives in site.js; ocean.js render loop uploads `state.night` per frame — satisfies "animate u_night in the render loop" (unanimous).
- `color-scheme` meta stays `light` (skeptic) over `light dark` (perf).
- Storage key `theme`; auto = follow OS; 3 scripts per page (inline + ocean.js + site.js).
- Theme crossfade kept under reduced motion (designer).

## Outcome

**Shipped:**
- **Theme toggle:** cycles auto → night → day and stores the choice under the `theme` key. An inline head script applies the theme before first paint, so there is no flash.
- **`site.js` (new, 3.3 KB):** a delegated toggle handler, an OS-scheme listener that only applies in auto mode, and a smoothstep tween of `__ocean.night` that exactly matches the CSS `cubic-bezier(1/3,0,2/3,1)`.
- **Colour transition:** `@property`-registered `--paper`, `--ink` and `--surface`, with a single 900 ms transition on `html`.
- **`ocean.js`:** seeds the night value from the page's theme class and exposes `state.redraw` for the static tier. Size is 10,190 B, which leaves 50 B of headroom.
- **Shader:** `gray *= mix(1.0, NIGHT_DIM=0.32, u_night)`. Day output is unchanged.

**Validation:**
- `zola check`/`zola build` and `node --check` on both JS files all pass.
- `m3check.mjs` passed 23/23 three runs in a row after it was switched to polling waits. The earlier failures were caused by fixed sleeps during SwiftShader main-thread stalls, not by the code.
- `lifecycle.mjs` passes.
- **Night contrast** of `#e8e6e1` against sampled shader pixels:

  | Text | Worst-case contrast | Target |
  |---|---|---|
  | Hero h1 | 4.60 or better | ≥ 3 |
  | Hero p | 4.97 or better | ≥ 4.5 |
  | Footer | 13.5 | ≥ 4.5 |

- **Day:** the sky pixels are identical to M2.

**Deferred:**
- Static-tier redraws during a tween advance wave time by up to 0.1 s per tick, which is cosmetic. Freezing it needs bytes that `ocean.js` doesn't have; revisit in M6 or when the budget is reworked.
- Everything listed under Deferred above.

**Surprises:**
- `@property` colours interpolate in oklab, so the midpoint is darker than an sRGB average would be.
- `ocean.js` has only 50 B of headroom left, so M4's content throttle will need a budget decision or the logic will have to live in `site.js`.
