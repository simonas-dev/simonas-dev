# M5 — htmx navigation

Question: best implementation plan for M5 of PLAN.md given scout context (`.council/M5-scout.md`).
Scope: M5 checklist + vendoring htmx, re-running `oceanMode()` on swap, closing the mobile menu, title updates, focus after swap, reduced motion for page animations. Non-goals: M6 polish; PLAN non-goals. `ocean.js` is not touched (2 B headroom).

## Plan (ordered steps)

1. **Vendor htmx** 2.0.11 `dist/htmx.min.js` unmodified → `static/htmx.min.js` (≈52 KB raw, ≈17 KB gzip). Record version + sha256 in Outcome. Download to /tmp first (npm tarball), don't add package files.
2. **`templates/base.html`**:
   - `<meta name="htmx-config" content='{"refreshOnHistoryMiss":true,"includeIndicatorStyles":false}'>` (add other config only if needed, e.g. `historyCacheSize`).
   - `<script src="/htmx.min.js" defer>` after ocean.js, before site.js.
   - Boost attributes on **`<body>`** (deviation from PLAN wording, which says div.page; nav/logo/footer links live outside `.page`): `hx-boost="true" hx-select="div.page" hx-target="div.page" hx-swap="outerHTML swap:220ms show:window:top"`.
   - **`hx-history-elt` on `div.page`** — mandatory, otherwise history restore replaces `<body>` and destroys `canvas#ocean` + GL context.
   - `tabindex="-1"` on `main#main`; `hx-boost="false"` on the RSS link.
3. **`static/site.js`** new htmx section (listeners on `document`, no-op if htmx absent):
   - `fullNav(url)` helper → `location.assign(url)`.
   - `htmx:beforeRequest`: if the target path's last segment has a file extension other than `.html` (e.g. the `.apk`), or link has `download`/foreign `target` → `preventDefault()` + `fullNav`. Also close `.menu` (`open = false`) for instant feedback.
   - `htmx:beforeSwap`: if response isn't `text/html` or lacks the `div.page`/`hx-history-elt` marker (alias pages, odd 200s) → `shouldSwap = false` + `fullNav`. Non-2xx responses → `fullNav` (shows the real 404 etc.).
   - `htmx:responseError`, `htmx:sendError`, `htmx:swapError`, `htmx:targetError`, `htmx:timeout` → `fullNav(elt.href || pathInfo.requestPath)`. `htmx:historyCacheMissLoadError` → `location.reload()`.
   - `htmx:afterSettle` (boosted) and `htmx:historyRestore`: `oceanMode()`, close menu; after a boosted forward swap only: `#main.focus({preventScroll:true})`.
   - Scroll: forward nav scrolls to top via `show:window:top`; back/forward relies on htmx history snapshot scroll restore. If the browser's native restoration races htmx, set `history.scrollRestoration = 'manual'` (verify in test).
4. **`static/styles.css`** — animate **`#main > *`**, not `.page` (opacity/transform on an ancestor makes it a backdrop root and kills `.content-surface` backdrop-filter mid-animation). Use **transitions**, not keyframes (htmx removes `.htmx-added` after the 20 ms settle):
   - `#main > * { transition: opacity 220ms var(--ease), transform 220ms var(--ease); }`
   - `.page.htmx-swapping #main > *, .page.htmx-added #main > * { opacity: 0; transform: translateY(.5rem); }`
   - `@media (prefers-reduced-motion: reduce)`: no transform, opacity fade kept (fade is not vestibular motion; keeps swap timing uniform).
   - `#main:focus { outline: none; }`. First load must not animate.
5. Validate: `/tmp/pw/m5check.mjs` (polling waits), re-run m4check, m3check, lifecycle.

## Acceptance checks

- **Boost**: clicking nav/logo/post links issues XHR (no document load); `#ocean` same node (stored JS reference) and GL context not lost; `document.title` updates; ocean switches to fps 15/res .5/speed .15 on content pages and back to 0/1/1 on `/` after swaps and after back; mobile menu closes after a menu link click; `activeElement` is `#main` after forward swap.
- **Animations**: `.page.htmx-swapping` present during the 220 ms window and new content goes opacity 0→1; computed transform `none` under emulated reduced motion; first load has no animation; mid-transition screenshot shows no blur/backdrop glitch on the panel.
- **Scroll**: scroll `/posts/` (or a long page) down, click a link → `scrollY` 0; back → `scrollY` restored (±2 px) with canvas node unchanged; forward → correct page. Back across a full-load boundary keeps the theme correct.
- **Fallback**: boosted link to a missing URL → full load shows the 404; route-aborted request (`sendError`) → full navigation; `.apk` and RSS links are not XHR'd; `/posts/wizard` still resolves; history cache miss (localStorage cleared) still works.
- **Budgets/global**: `ocean.js` unchanged (10,238 B); total JS raw < 150 KB; `zola check` + `zola build` pass; no console errors; with JS disabled, plain links still work.

## Review loop

- **Round 1.** Worker ca3259e5. Reviewers: htmx semantics (3598395b) and a11y/perf/visual (2dcbef9b).
  - **P1:** a rapid-click race. htmx 2.0.11 picks the swap target when the request starts and releases its lock before the 220 ms delayed swap. Two clicks close together therefore produced a URL/title/content mismatch and a corrupted history cache. Pressing back during the swap window had the same effect.
  - **P2s:** the `swapError` listener was dead code, and the content-check fallback dropped the fragment.
- **Round 2.** Worker daebfaee fixed these in `site.js`:
  - **Single navigation at a time:** a pending-navigation guard, with only the latest click queued and replayed after settle.
  - **Back while a request is in flight:** the late response is dropped.
  - **Back while a swap is scheduled:** history writes are disabled and the page reloads.
  - **Fallback fragment:** now preserved.
  - Three cases were added to m5check: rapid double clicks, back during the swap window, and the skip link after a swap. The pre-fix code fails them (60/69); the fixed code passes them.
- **Round 2 review (0df749a2): OK with notes.** The supervisor applied its three P2s directly:
  - queued clicks are timestamped, so htmx's own replay of an older click can't override the newest one;
  - the download guard uses `location.assign` and no longer clears the pending-navigation state;
  - `htmx:onLoadError` was added to the full-navigation fallbacks.
- Stopped after round 2: no P0 or P1 findings remain.

## Outcome

**Shipped:**
- **htmx:** 2.0.11 vendored as `static/htmx.min.js` (52,182 B raw, 16,885 B gzip -9; sha256 `d6fdc75f204e6bdefa99b69bf1e6d4ac69b8a364f77929f45c13476b4000f717`).
- **Boost wiring:** the boost attributes sit on `<body>` and `hx-history-elt` on `div.page`. The canvas, header and footer persist across navigation.
- **Page transitions:** `#main > *` fades with opacity and transform. Reduced motion keeps the fade but drops the transform. `.page` itself is never animated, so the panel's backdrop blur stays intact.
- **After each swap:** focus moves to `#main` and `oceanMode()` re-runs, which applies the 15 fps / 0.5× / 0.15 settings on content pages.
- **Menu:** closes on navigation.
- **Full-load fallbacks:** non-HTML responses, alias pages, HTTP errors, network errors, timeouts and load errors all fall back to a full page load. Downloads (the `.apk`) and RSS are never fetched over XHR.
- **Concurrency guard:** only one navigation runs at a time; see the review loop above.
- **Owner's wordmark change:** the header logo uses Departure Mono at the mono size, with an underline on hover. This was applied during M5 per decisions.md and is included in this commit.

**Validation:**
- `zola check` and `zola build` pass; `node --check` passes.
- m5check 69/69: XHR-only navigation, the same canvas node with no context loss across forward/back/forward, titles, `oceanMode` values, menu, focus, animation frames, reduced motion, scroll to top on forward and restore on back, the 404 and abort fallbacks, `.apk` and RSS, history-cache miss, theme after back across a full load, rapid clicks, and the skip link.
- m4check 91/91, m3check 23/23, lifecycle PASS.
- Total JS is 71,642 B raw (htmx 52,182 + ocean 10,238 + site ~9.4 KB), well under 150 KB. `ocean.js` is unchanged.
- The timing-based checks are flaky under heavy machine load, because a parallel lane (M6a) was running at the same time. They passed on reruns.

**Deferred:**
- To M6: a speed tween between ocean modes, `aria-current`, a live-region title announcement, and updating the meta description on swap.
- Prefetch and View Transitions.
- Cross-page hash anchors.
- Pressing back during the 220 ms swap window does a full reload instead of an in-place restore. This was accepted.

**Surprises:**
- htmx 2.0.11 keeps its history cache in sessionStorage.
- The `swapError` event never fires when a swap delay is set.
- The rapid-click race was not caught by the council; reviewers found it by reading the htmx source.
